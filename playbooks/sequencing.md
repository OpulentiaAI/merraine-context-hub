# Sequencing

# Job
Write a short run of notes that depends on itself and then stops.
Write the last note first. If step three does not need step two, it
is a schedule, not a sequence.

# Process
1. Name the end state. A reply, a pass, or a booked 15 minutes.
2. Write the last note first. See [[sequence-write-the-end-first]].
3. Each earlier note teaches one thing and asks one action.
4. Default cadence: first touch → bump at day 5 → breakup at day 12 → stop.
   LinkedIn does not get a long run. Email can hold the later steps
   once Gmail is connected.
5. Exit on reply, on a no, on an open search, on suppression, on OOO
   until the named return. See [[baur-exit-on-reply]].
6. Create the Spear campaign paused. `sendReady: no`.

# Output
```
# Sequence — [company or pack] — [date]
End state: [reply | pass | 15 min]
Steps: 2 or 3
| Step | Day | Channel | Job | Action | Exit if |
```

# Guardrails
- Do not keep mailing after they did the thing.
- Do not run a four-step LinkedIn drip.
- A purchased list is not a sequence input.
